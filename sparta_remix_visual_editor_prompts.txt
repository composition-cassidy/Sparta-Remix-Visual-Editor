================================================================================
SPARTA REMIX VISUAL EDITOR (SRVE) - DEVELOPMENT PROMPTS
================================================================================

PROJECT OVERVIEW:
A desktop application for creating Sparta Remix/YTPMV visuals. Uses MIDI data to
automatically align video clips to audio. Python backend (FFmpeg + MIDI parsing),
Electron frontend (React UI). Saves projects as .srf (Sparta Remix File).

TECH STACK:
- Backend: Python 3.10+, FastAPI, ffmpeg-python, mido (MIDI), numpy
- Frontend: Electron, React, TypeScript
- Communication: REST API + WebSocket for real-time updates
- Video Processing: FFmpeg (subprocess calls)

PROMPT 6A - NOTE TIMING AND CLIP GENERATION:

"""
Implement the core engine that converts MIDI notes to video clip placements.

BACKEND - core/renderer.py:

1. Create class RenderEngine:

   __init__(self, project: Project, midi_data: MidiData)
   
2. generate_clip_list(self, layer: Layer) -> list[ClipPlacement]:
   
   ClipPlacement model:
   - start_ms: int (timeline position)
   - duration_ms: int
   - source_start_ms: int (position in source video)
   - velocity: int (0-127)
   - flip_state: Literal["normal", "h_flip", "v_flip", "hv_flip"]
   - clip_index: int (which note this is, for alternating effects)
   
   Logic:
   - Get notes for this layer's MIDI channel
   - For each note:
     a. Determine clip start_ms from note start
     b. Determine duration:
        - If note_length_mode == "midi": use note duration
        - Else: calculate from BPM (e.g., 1/16 at 120 BPM = 125ms)
     c. Determine source_start_ms:
        - Start from layer's in_point
        - If previous clips used source video, continue from where last clip ended
        - If reached out_point, apply loop_mode:
          * "freeze": stay at out_point
          * "continue": keep going past out_point
          * "crossfade": will need special handling in FFmpeg
     d. Apply flip_state based on flip_mode and clip_index
     e. Store velocity for opacity calculation

3. calculate_flip_state(self, flip_mode: FlipMode, clip_index: int) -> str:
   - NONE: always "normal"
   - ALTERNATING: "normal" if even, "h_flip" if odd
   - ROTATION_CW: cycle through ["normal", "h_flip", "hv_flip", "v_flip"]
   - ROTATION_CCW: cycle through ["normal", "v_flip", "hv_flip", "h_flip"]

4. generate_all_clips(self) -> dict[str, list[ClipPlacement]]:
   - Returns dict mapping layer_id to clip list
   - Only process enabled layers

DO NOT:
- Do not generate FFmpeg commands yet
- Do not implement the actual rendering yet
- Do not handle overlapping notes specially (just place them, FFmpeg handles compositing)
"""

PROMPT 6B - FFMPEG FILTER CHAIN GENERATION:

Implement FFmpeg filter chain generation for rendering.

BACKEND - utils/ffmpeg_utils.py:

1. generate_clip_filter(

    layer: Layer,

PROMPT 7C - ZOOM EFFECT WITH EASING:

"""
Implement the zoom-within-box effect with easing functions.

BACKEND - utils/math_utils.py:

1. Implement easing functions:

   def ease_linear(t: float) -> float:
       return t
   
   def ease_in(t: float, intensity: float = 1.0) -> float:
       return pow(t, 1 + intensity)
   
   def ease_out(t: float, intensity: float = 1.0) -> float:
       return 1 - pow(1 - t, 1 + intensity)
   
   def ease_smooth(t: float, intensity: float = 1.0) -> float:
       # Smoothstep or bezier curve
       t = t * t * (3 - 2 * t)  # Basic smoothstep
       return t
   
   def ease_elastic(t: float, intensity: float = 1.0) -> float:
       # Elastic/bounce effect
       if t == 0 or t == 1:
           return t
       p = 0.3 / intensity
       return pow(2, -10 * t) * sin((t - p/4) * (2 * PI) / p) + 1

2. def calculate_zoom_scale(
    t: float,           # Progress 0-1 through clip
    start_scale: float,
    end_scale: float,
    easing: EasingType,
    intensity: float
) -> float:

   - Interpolate between start_scale and end_scale
   - Return scale factor

    zoom_settings: ZoomEffect,
    clip_duration_ms: int,
    cell_size: tuple[int, int],
    fps: float
) -> str:

   Approach A - Frame-by-frame scale (accurate but verbose):
   - Pre-calculate scale for each frame
   - Generate zoompan or scale filter with sendcmd
   
   Approach B - Use zoompan filter with expression:
   - zoompan=z='min(max_zoom, 1+progress*delta)':d=duration_frames
   - Limited easing options
   
   Approach C - Use scale with animate:
   - scale=w='iw*{scale_expr}':h='ih*{scale_expr}'
   - Where scale_expr uses frame number N
   
   For elastic easing, may need to pre-render or accept approximation.
   
   Recommended: Start with Approach C for linear/ease_in/ease_out
   - Expression: 'start + (end-start) * (N/total_frames)^power'

   - Zoom is centered, so crop from center

- Do not worry about sub-frame precision

       # Gzip compress
       compressed = gzip.compress(json_data.encode('utf-8'))
       # Add magic bytes header: "SRF1" (4 bytes)
